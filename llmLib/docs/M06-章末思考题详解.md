# 章末思考题详解

## 问题 1：NL2SQL 表结构按需获取

### 问题背景

NL2SQL 需要表结构信息来生成准确的 SQL。当数据库规模很大时（几百张表、几千个字段），将完整 Schema 加载到提示词会：
- 超出上下文窗口限制
- 增加推理成本
- 降低模型准确性（噪音过多）

### 核心策略：分层检索 + 动态加载

#### 1. Schema 元数据索引

首先建立轻量级的 Schema 索引，只存储关键信息：

```go
type SchemaIndex struct {
    Tables []TableInfo `json:"tables"`
}

type TableInfo struct {
    Name        string   `json:"name"`
    Description string   `json:"description"`  // 表的业务含义
    RowCount    int64    `json:"row_count"`     // 用于评估相关性
    Columns     []Column `json:"columns"`
    ForeignKeys []FK     `json:"foreign_keys"`  // 关联关系
}

type Column struct {
    Name         string `json:"name"`
    Type         string `json:"type"`
    Description  string `json:"description"`
    IsPrimaryKey bool   `json:"is_primary_key"`
    IsForeignKey bool   `json:"is_foreign_key"`
}
```

**存储策略：**
- 将 SchemaIndex 序列化为 JSON，大小通常在 10-50KB
- 存入向量数据库（如 pgvector、Weaviate）或专门的特征存储
- 定期更新（Schema 变更时）

#### 2. 两阶段检索

**阶段一：候选表筛选**

```go
// 基于用户问题检索相关表
func RetrieveCandidateTables(question string, index SchemaIndex) ([]TableInfo, error) {
    // 方法1：关键词匹配
    keywords := extractKeywords(question)
    scored := scoreTablesByKeywords(index.Tables, keywords)

    // 方法2：语义相似度（推荐）
    embedding, err := generateEmbedding(question)
    if err == nil {
        semanticMatches := vectorSearch(embedding, index.Tables)
        scored = mergeScores(scored, semanticMatches)
    }

    // 取 Top-K（K=3-5）
    return topK(scored, 5), nil
}
```

**阶段二：关联表扩展**

```go
// 获取候选表的所有关联表（1-N跳）
func ExpandRelatedTables(tables []TableInfo, index SchemaIndex) []TableInfo {
    var result []TableInfo
    visited := make(map[string]bool)

    var dfs func(tableName string, depth int)
    dfs = func(tableName string, depth int) {
        if visited[tableName] || depth > 1 {
            return
        }
        visited[tableName] = true

        // 查找当前表
        for _, t := range index.Tables {
            if t.Name == tableName {
                result = append(result, t)
                // 递归查找外键关联表
                for _, fk := range t.ForeignKeys {
                    dfs(fk.ReferencedTable, depth+1)
                }
            }
        }
    }

    for _, t := range tables {
        dfs(t.Name, 0)
    }
    return result
}
```

#### 3. 动态 Schema 注入

```go
func BuildSchemaPrompt(tables []TableInfo) string {
    var sb strings.Builder
    sb.WriteString("## Database Schema\n\n")

    for _, table := range tables {
        sb.WriteString(fmt.Sprintf("### %s\n", table.Name))
        if table.Description != "" {
            sb.WriteString(fmt.Sprintf("Description: %s\n", table.Description))
        }

        sb.WriteString("Columns:\n")
        for _, col := range table.Columns {
            pk := ""
            if col.IsPrimaryKey {
                pk = " (PRIMARY KEY)"
            }
            sb.WriteString(fmt.Sprintf("- %s %s%s: %s\n",
                col.Name, col.Type, pk, col.Description))
        }

        if len(table.ForeignKeys) > 0 {
            sb.WriteString("Foreign Keys:\n")
            for _, fk := range table.ForeignKeys {
                sb.WriteString(fmt.Sprintf("- %s -> %s.%s\n",
                    fk.Column, fk.ReferencedTable, fk.ReferencedColumn))
            }
        }
        sb.WriteString("\n")
    }

    return sb.String()
}
```

#### 4. 完整流程示例

```go
func NL2SQLWithDynamicSchema(question string) (string, error) {
    // 1. 加载 Schema 索引
    index, err := loadSchemaIndex("schema-index.json")
    if err != nil {
        return "", err
    }

    // 2. 检索候选表
    candidateTables := RetrieveCandidateTables(question, index)

    // 3. 扩展关联表
    relevantTables := ExpandRelatedTables(candidateTables, index)

    // 4. 构建 Schema Prompt（仅包含相关表）
    schemaPrompt := BuildSchemaPrompt(relevantTables)

    // 5. 调用 LLM
    prompt := fmt.Sprintf(`
%s

Question: %s

Generate SQL query (read-only mode):
`, schemaPrompt, question)

    sql, err := llm.Call(prompt)
    return sql, err
}
```

## 问题 2：MCP 工具按需暴露

### 问题背景

MCP Tool Bridge 默认注册 Server 的所有工具。当 Server 提供几十个工具时：
- 每个工具描述占用 100-300 tokens
- 工具数量增加导致 prompt 过长
- 低相关工具干扰模型决策

### 核心策略：工具过滤 + 动态注册

#### 1. 基于意图的工具过滤

```go
type ToolFilter interface {
    Filter(tools []Tool, context TaskContext) []Tool
}

// 关键词过滤
type KeywordFilter struct {
    Keywords map[string][]string // 工具名 -> 关键词
}

func (f *KeywordFilter) Filter(tools []Tool, ctx TaskContext) []Tool {
    question := strings.ToLower(ctx.Question)
    var filtered []Tool

    for _, tool := range tools {
        keywords, ok := f.Keywords[tool.Name]
        if !ok {
            continue
        }
        for _, kw := range keywords {
            if strings.Contains(question, strings.ToLower(kw)) {
                filtered = append(filtered, tool)
                break
            }
        }
    }
    return filtered
}
```

#### 2. 基于 Embedding 的语义过滤

```go
type SemanticFilter struct {
    toolEmbeddings map[string][]float64 // 工具名 -> embedding
    threshold      float64
}

func NewSemanticFilter(tools []Tool) *SemanticFilter {
    f := &SemanticFilter{
        toolEmbeddings: make(map[string][]float64),
        threshold:      0.75,
    }

    // 预计算工具描述的 embedding
    for _, tool := range tools {
        embedding, _ := generateEmbedding(tool.Description)
        f.toolEmbeddings[tool.Name] = embedding
    }

    return f
}

func (f *SemanticFilter) Filter(tools []Tool, ctx TaskContext) []Tool {
    questionEmb, err := generateEmbedding(ctx.Question)
    if err != nil {
        return tools // 降级：返回所有工具
    }

    var filtered []Tool
    for _, tool := range tools {
        similarity := cosineSimilarity(questionEmb, f.toolEmbeddings[tool.Name])
        if similarity > f.threshold {
            filtered = append(filtered, tool)
        }
    }

    // 确保至少返回 2-3 个工具（避免过度过滤）
    if len(filtered) < 2 && len(tools) > 0 {
        return tools[:min(3, len(tools))]
    }
    return filtered
}
```

#### 3. 分层工具注册

```go
type LayeredToolRegistry struct {
    coreTools    []Tool // 始终暴露（2-3 个）
    domainTools  []Tool // 基于意图暴露（5-10 个）
    specialTools []Tool // 特殊任务触发（按需）
}

func (r *LayeredToolRegistry) RegisterForTask(ctx TaskContext) []Tool {
    var result []Tool

    // 1. 始终注册核心工具
    result = append(result, r.coreTools...)

    // 2. 基于意图选择领域工具
    domainTools := filterByIntent(r.domainTools, ctx)
    result = append(result, domainTools...)

    // 3. 特殊条件触发
    if requiresSpecialTools(ctx) {
        specialTools := filterSpecialTools(r.specialTools, ctx)
        result = append(result, specialTools...)
    }

    return result
}
```

#### 4. 集成到 MCPToolBridge

```go
type SmartMCPToolBridge struct {
    mcpBridge    *MCPToolBridge
    toolFilter   ToolFilter
    registry     *LayeredToolRegistry
    tokenBudget  int // 工具描述的总 token 预算
}

func NewSmartMCPToolBridge(client *mcp.Client, opts ...BridgeOption) *SmartMCPToolBridge {
    bridge := &SmartMCPToolBridge{
        mcpBridge:  NewMCPToolBridge(client),
        tokenBudget: 2000, // 工具描述总预算
    }

    for _, opt := range opts {
        opt(bridge)
    }

    return bridge
}

func (b *SmartMCPToolBridge) RegisterTools(ctx context.Context, taskContext TaskContext) error {
    // 1. 获取所有 MCP 工具
    allTools, err := b.mcpBridge.LoadTools(ctx)
    if err != nil {
        return err
    }

    // 2. 应用过滤器
    filteredTools := b.toolFilter.Filter(allTools, taskContext)

    // 3. Token 预算检查
    filteredTools = enforceTokenBudget(filteredTools, b.tokenBudget)

    // 4. 注册到 Registry
    for _, tool := range filteredTools {
        b.mcpBridge.Register(tool)
    }

    return nil
}

func enforceTokenBudget(tools []Tool, budget int) []Tool {
    var result []Tool
    totalTokens := 0

    for _, tool := range tools {
        tokens := estimateTokens(tool.Description + tool.Parameters)
        if totalTokens+tokens <= budget {
            result = append(result, tool)
            totalTokens += tokens
        }
    }

    return result
}
```

```go
func OptimizeToolDescription(tool Tool) Tool {
    // 压缩描述到 100 tokens 以内
    optimized := Tool{
        Name:        tool.Name,
        Description: truncateToTokens(tool.Description, 100),
        Parameters:  tool.Parameters,
    }
    return optimized
}

func truncateToTokens(text string, maxTokens int) string {
    // 简单实现：按字符比例截断（实际应用用 tiktoken）
    approxChars := maxTokens * 4
    if len(text) <= approxChars {
        return text
    }
    return text[:approxChars-3] + "..."
}
```

```go
func ModelBasedSelection(tools []Tool, question string) ([]Tool, error) {
    toolList := make([]string, len(tools))
    for i, t := range tools {
        toolList[i] = fmt.Sprintf("%d. %s: %s", i, t.Name, t.Description)

Select the most relevant tools (respond with numbers only):

Selected tools:`, question, strings.Join(toolList, "\n"))

    selectedIndices := parseSelectedIndices(result)

    }

}
```

## 问题 3：工具结果压缩与外置

### 问题背景

工具返回的长文档（如数据库查询结果、文件内容、API 响应）会迅速消耗上下文：
- 一次查询可能返回数千行数据
- 多个工具结果累积成"上下文膨胀"
- 超出窗口限制或稀释模型注意力

### 核心策略：分层压缩 + 外部存储

#### 1. 结果分级策略

```go

const (
```

#### 2. 智能压缩函数

```go
func CompressToolResult(result string, strategy CompressionStrategy) string {
    // 策略 1：固定长度截断
    if strategy == StrategyTruncate {
        return truncate(result, 2000)
    }

    // 策略 2：统计摘要（结构化数据）
    if strategy == StrategyStructuredSummary {
        return generateStructuredSummary(result)
    }

    // 策略 3：LLM 压缩（长文本）
    if strategy == StrategyLLMCompress && len(result) > 4000 {
        return llmCompress(result)
    }

    // 策略 4：外置存储 + 引用
    if strategy == StrategyExternalize && len(result) > 8000 {
        return externalize(result)
    }

    return result
}
```

#### 3. 结构化数据压缩

```go
// 对 CSV/JSON/表格数据生成统计摘要
func generateStructuredSummary(data string) string {
    // 尝试解析为 JSON
    var jsonData interface{}
    if err := json.Unmarshal([]byte(data), &jsonData); err == nil {
        return summarizeJSON(jsonData)
    }

    // 尝试解析为 CSV
    records := parseCSV(data)
    if records != nil {
        return summarizeCSV(records)
    }

    // 降级：行数 + 前几行
    lines := strings.Split(data, "\n")
    return fmt.Sprintf("Total lines: %d\nFirst 5 lines:\n%s",
        len(lines), strings.Join(lines[:5], "\n"))
}

func summarizeJSON(data interface{}) string {
    switch v := data.(type) {
    case []interface{}:
        return fmt.Sprintf("Array with %d items. Sample: %v",
            len(v), v[0:min(3, len(v))])
    case map[string]interface{}:
        keys := make([]string, 0, len(v))
        for k := range v {
            keys = append(keys, k)
        }
        return fmt.Sprintf("Object with keys: %v", keys)
    default:
        return fmt.Sprintf("Value: %v", v)
    }
}
```

```go
func llmCompress(text string) (string, error) {
    prompt := fmt.Sprintf(`
Compress the following text while preserving key information.
Target length: ~500 tokens.

Text:
%s

Compressed version:`, text)

    compressed, err := llm.Call(prompt)
    if err != nil {
        return "", err

    return compressed, nil

// 增量压缩：维护压缩历史
type CompressionContext struct {
    original   string
    compressed string
    keyPoints  []string
}

func IncrementalCompress(text string, history []CompressionContext) string {
    // 将历史关键点与新文本结合
    var keyPoints []string
    for _, h := range history {
        keyPoints = append(keyPoints, h.keyPoints...)
    }

    prompt := fmt.Sprintf(`
Previous key points: %v

New text: %s

Generate updated summary incorporating previous key points:`,
        keyPoints, text)

    summary, _ := llm.Call(prompt)
    return summary
}
```

#### 7. 集成到 Agent 循环

```go
type ContextManager struct {
    storage      ExternalStorage
    maxTokens    int
    currentTokens int
}

func (cm *ContextManager) AddToolResult(result string, toolName string) error {
    compressed := CompressToolResult(result, cm.selectStrategy(result))

    // 检查 token 预算
    tokens := estimateTokens(compressed)
    if cm.currentTokens+tokens > cm.maxTokens {
        // 触发压缩或外置
        return cm.handleOverflow(compressed, toolName)
    }

    cm.currentTokens += tokens
    cm.appendToContext(compressed)
    return nil
}

func (cm *ContextManager) handleOverflow(result string, toolName string) error {
    // 策略 1：压缩已有结果
    if err := cm.compressOldResults(); err == nil {
        cm.appendToContext(result)
        return nil
    }

    // 策略 2：外置新结果
    ref, err := cm.storage.Store(toolName, result)
    if err != nil {
        return err
    }

    summary := generateSummary(result)
    cm.appendToContext(fmt.Sprintf("**%s**: %s (stored at %s)",
        toolName, summary, ref))
    return nil
}
```

```go
// "简要说明" → Level1
// "详细分析" → Level2/Level3
// "原始数据" → Full (检索)
```

#### 方案 C：增量更新

```go
type IncrementalResult struct {
    BaseSummary string      // 基础摘要
    Deltas      []Delta    // 增量更新
}

type Delta struct {
    Timestamp time.Time
    Content   string
    Summary   string
}

// 避免重复存储相同内容
func MergeResults(old, new string) string {
    if isSubset(new, old) {
        return old // 新结果是旧结果的子集
    }
    // 计算增量
    delta := computeDelta(old, new)
    return fmt.Sprintf("%s\n\n**Updates**: %s", old, delta)
}
```

### 最佳实践

1. **压缩优先级**：统计摘要 > LLM 压缩 > 采样 > 外置
2. **外置触发阈值**：> 8000 tokens（约 2000 行文本）
3. **引用保留**：外置后保留 100-200 token 的摘要 + 引用
4. **可检索性**：外置数据应支持语义检索
5. **缓存策略**：工具结果缓存 1-24 小时（根据数据更新频率）
6. **降级机制**：存储失败时回退到截断

## 总结对比

| 策略 | 问题 1 (Schema) | 问题 2 (MCP Tools) | 问题 3 (Results) |
|------|----------------|-------------------|-----------------|
| **核心思路** | 按需加载 | 按需暴露 | 按需保留 |
| **关键技术** | Embedding + 向量检索 | 语义过滤 + Token 预算 | 压缩 + 外置 + RAG |
| **Token 控制** | Schema 占总 prompt 30-40% | 工具描述预算 1000-2000 | 结果保留 < 2000 tokens |
| **降级方案** | 关键词匹配 | 返回所有工具 | 截断 |
| **缓存策略** | SchemaIndex 缓存 24h | 工具过滤结果缓存 | 结果缓存 1-24h |

三个问题本质相同：**如何在海量信息中只加载当前任务真正需要的内容**。答案都遵循"检索-过滤-压缩"的三步模式。
