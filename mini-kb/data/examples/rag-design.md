# 知识库问答系统设计

## 什么是 RAG？

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与语言模型生成相结合的 AI 架构。

## RAG 的核心流程

1. **索引阶段**：将文档切分成小块，创建向量索引。
2. **检索阶段**：根据用户查询，从索引中检索相关块。
3. **生成阶段**：将检索到的块作为上下文，由语言模型生成答案。

## 为什么需要 RAG？

语言模型的训练数据有截止日期，无法获取最新信息。RAG 通过外部知识库解决这个问题，使 AI 能够：
- 回答训练数据之外的问题
- 提供可验证的答案来源
- 减少模型幻觉（Hallucination）

## 向量检索

向量检索将文本转换为高维向量，然后通过相似度搜索找到相关内容。
常用的向量数据库包括 Milvus、Pinecone、Weaviate 等。

## 混合检索

混合检索结合多种检索方式：
- **关键词检索**：基于 BM25 等经典算法
- **向量检索**：基于语义相似度
- **重排序**：使用交叉编码器对初步结果进行精排

## Agentic RAG

Agentic RAG 让 AI Agent 自主决定何时检索、检索什么：
- Agent 判断问题是否需要检索
- Agent 可以多次检索不同来源
- Agent 根据检索结果决定是否需要进一步搜索

## 记忆系统

短期记忆保存当前会话的历史对话，使 AI 能够理解上下文。
长期记忆保存用户的偏好和重要事实，跨会话使用。

## 工程实践

生产级 RAG 系统需要考虑：
- 文档预处理和切分策略
- 嵌入模型选择
- 检索质量和延迟的平衡
- 缓存策略减少重复检索
- 错误处理和降级机制
