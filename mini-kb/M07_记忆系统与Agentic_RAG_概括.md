## 一、Agent 的记忆系统

### 1. 为什么需要记忆
- LLM **完全无状态**，每次 API 调用孤立，不记得之前的对话。
- Agent 任务有状态（对话历史、用户偏好、过去交互、业务知识），必须在外层包一层记忆系统。

### 2. 四种记忆类型（借鉴认知科学 CoALA 框架）

| 类型 | 内容 | 典型存储 | 生命周期 |
|------|------|----------|----------|
| **工作记忆** | 当前对话上下文、ReAct 推理轨迹 | 内存数组 + checkpoint | 单次会话 |
| **情节记忆** | 过去会话、历史交互 | PostgreSQL + 向量库 | 跨会话持久化 |
| **语义记忆** | 事实知识、企业文档、API 规范 | 向量库 + 全文索引（RAG） | 与时间无关 |
| **程序记忆** | 技能、工作流、行为规则 | system prompt、Skills 模板 | 版本管理 |

### 3. 工程三问：写什么 / 读什么 / 丢什么
- **写**：不是所有信息都该存，业界通用「摘要 + 实体抽取」。
- **读**：何时检索、检索多少、怎么排序 —— 混合检索 + rerank 回答。
- **丢**：LRU / LFU / 时间衰减 / 重要性+时间四种淘汰策略，情节记忆模仿人脑遗忘曲线。

### 4. 记忆 ≠ 上下文 ≠ 知识库
- **上下文** = 单次调用的所有 token（瞬时）。
- **记忆** = 跨调用持久化的信息池（持久）。
- **知识库** = 语义记忆的具体载体。

## 二、RAG（检索增强生成）

### 1. RAG 的形式化定义
```
RAG = Retriever（检索器） + Generator（生成器） + Augmented Prompt（增强提示词）
```

### 2. RAG 三步骨架
| 步骤 | 动作 | 时机 |
|------|------|------|
| 索引 | 文档切块 → Embedding 向量化 → 存入向量库 | 离线 |
| 检索 | 问题向量化 → 向量库找最相似 K 个 | 在线（秒级） |
| 生成 | 检索块作为上下文 + 问题 → 发给模型生成回答 | 在线 |

### 3. RAG vs Fine-tuning

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| 知识更新 | 改资料即生效 | 重训（几小时~几天） |
| 来源追溯 | ✅ 可标注出处 | ❌ 知识混入权重 |
| 数据合规 | 数据不进模型 | 数据进权重，难删除 |
| 适用场景 | **95% 企业场景** | 风格/语气定制、特定任务模式 |

### 4. RAG 演进谱系

| 代际 | 名称 | 核心思路 |
|------|------|----------|
| 第 1 代 | Naive RAG (2020) | 分句切分 → 单 Embedding → top-K → 生成 |
| 第 2 代 | Hybrid RAG (2023) | BM25+向量双路召回 + RRF 融合 + Rerank |
| 第 3 代 | Agentic RAG (2024) | 检索包装成工具，Agent 自主决定检索时机/内容/充分性 |
| 第 4 代 | GraphRAG (2024末) | 抽取实体+关系建图，全局视角强，索引成本高 5-10x |
| 第 5 代 | 进行中 (2025+) | AgentMem、长上下文 Tuning、多模态 RAG |

### 5. RAG 的局限
- 不适合代码补全、翻译、计算密集型任务
- 全局视角弱（适合 GraphRAG）
- 精确匹配失效（运单号、ID 等 → 需 BM25）
- 多模态需专用模型

### 6. RAGAS 评估四维
| 维度 | 含义 | 低分对策 |
|------|------|----------|
| Context Recall | 该找的都找到了吗 | 改切分/Embedding/加混合检索 |
| Context Precision | 找到的都相关吗 | 加 Rerank/调 top-K |
| Faithfulness | 回答是否基于检索资料 | 改 prompt 要求引用来源 |
| Answer Relevancy | 是否答到点上 | 优化模型或 prompt |

## 三、Embedding（向量化）

### 1. 本质
把文本映射到 N 维向量空间，使「语义相近的文本位置也相近」。底层依据是 **分布假说**（Distributional Hypothesis）：出现在相同语境中的词，含义相似。

### 2. 三种训练范式
| 范式 | 核心方法 | 代表 |
|------|----------|------|
| Word2Vec | 窗口内中心词↔上下文预测 | GloVe |
| BERT/MLM | 整句双向还原被遮词；SBERT 加句对相似度 | SBERT |
| 对比学习 | 拉近正样本、推远负样本 | text-embedding-3、BGE-M3、Voyage |

### 3. 距离度量
- **余弦相似度**（最常用，95%+ 场景）：看方向，忽略长度。
- 欧氏距离、点积。

### 4. 模型选型要点
- 1536 维是性价比甜点
- 中文场景推荐 BGE-M3 / Qwen3-embedding
- 更换 Embedding 模型 = 全量重建向量库

## 四、文档切分

**RecursiveChunker**：按段落 → 句子 → 标点的优先级递归切分，相邻块保留 overlap。
- 中文推荐：ChunkSize 300~500 字，Overlap ~50 字。

---

## 五、向量数据库（pgvector）

### 1. 主流 ANN 算法对比
| 算法 | 召回率 | 查询速度 | 适合规模 |
|------|--------|----------|----------|
| Flat | 100% | O(N) | < 10 万 |
| IVF | 90-98% | O(√N) | 100 万~1 亿 |
| **HNSW** | 95-99% | O(log N) | 100 万~1 亿（默认选择） |

### 2. 选型建议
- < 1000 万 + 已有 PostgreSQL → **pgvector**（无额外运维、可与业务表 JOIN）
- 1000 万~10 亿 → Qdrant / Milvus
- SaaS 零运维 → Pinecone / Weaviate Cloud

## 六、混合检索与 Rerank（生产基线）

```
向量检索 top-50（语义）
  + BM25 全文检索 top-50（关键词）
  → RRF 融合（倒数排名融合，k=60）
  → Rerank 精排（交叉编码器）
  → top-5 进入上下文
```

这是当前**投入产出比最高**的优化手段。

---

## 七、HyDE（假设性文档嵌入）

先让 LLM 根据问题生成一段「假设答案」，再用假设答案（而非原问题）做向量检索。解决「用户口语化提问 vs 文档书面化」的风格错配问题。多一次模型调用，按需启用。

---

## 八、Agentic RAG

把检索包装成 Tool 注册给 Agent，让 Agent 自主决定：
- **何时检索**（说"谢谢"不检索）
- **检索什么**（自主提炼查询词，多跳问题多次检索）
- **够不够**（反思机制判断是否需要换查询再查）

---

## 九、GraphRAG / 长上下文 vs RAG

| 场景 | 推荐 |
|------|------|
| 具体事实查找 | 向量 RAG |
| 多跳关系 / 全局归纳 | GraphRAG |
| 语料小且稳定 + Prompt Caching | 长上下文 |
| 企业知识库（大语料 + 更新频繁 + 需引用） | RAG |

# 配套练习：mini-kb 知识库问答 — 项目要求

## 目标
实现一个可用的 Go 语言知识库问答工具，串联本章全部核心内容。

## 技术栈
- **语言**：Go
- **数据库**：PostgreSQL + pgvector（docker-compose 启动）
- **文档格式**：`.md` / `.txt`

## 功能需求

### 1. 索引管线
- 遍历本地文档目录（`filepath.WalkDir`）
- 用 `RecursiveChunker` 切分文档
- 调用 `Embedder` 批量向量化
- 通过 `PgVectorStore.Add` 入库

### 2. 检索管线
- 实现 `Retriever`，包含：
  - **向量检索**：pgvector 余弦相似度
  - **关键词检索**：PostgreSQL 全文检索（`tsvector`）
  - **RRF 融合**：两路结果合并排序
  - **Rerank 重排**：交叉编码器精排取 top-5

### 3. Agentic RAG 工具
- 把检索管线包装成 `SearchTool`，注册进 Agent
- 验证 Agent 会「按需检索」和「多查几次」（多跳问题）

### 4. 回答要求
- **必须带来源标注**（文档 ID + 相关度分数）
- 检索不到时如实说明「未找到」，**禁止编造**

### 5. 对比实验
- 同一问题分别跑「纯向量检索」和「混合+重排」，对比质量差异

### 6. 测试
- 为 `RRF`、`RecursiveChunker.Split`（含超长无分隔符硬切用例）写**表驱动测试**
